    Class 2.4 - R 中的数据类型¶

    在 R 中，我们基本就只会接触到以下几种数据类型：

    • 数值型（numeric）：包括整数（integer）与双精度数（double）
    • 逻辑型（logical）：只有 TRUE 和 FALSE 两种取值
    • 字符型（character）：文本数据
    • 因子型（factor）：带有类别信息的数据，建立在字符（或整数）的基础之上
    • 日期型（Date）：日期与时间数据，建立在数值的基础之上

    另外还有一个特殊的值：缺失值 NA，它可以出现在以上任何一种类型的数据中。

    本节课我们重点讲解数值型、逻辑型和缺失值以及相关操作，其他数据类型我们这里简单介绍，后续的进阶操作我们会在之后的课程中详细介绍。

    1. 数值型（numeric）¶

    数值型数据在 R 中又分为两种类型：整数（integer）与双精度数（double），其实就是大家理解的整数和小数

    (1) 整数与双精度数¶

    (a) 整数与双精度数的定义¶

    在 R 中，基本上所有的数字都是双精度数

    • 要想创建一个整数，我们需要在数字后面加上 L，比如 1L 就是一个整数
    • 而不加 L 的数字默认就是双精度数了，比如 1、3.14、-2.718 就是一个双精度数
    • 我们可以定义以下这几个变量来看看它们的类型，在 R 中，我们可以使用 typeof() 函数来查看一个变量的数据类型：
    a <- 1L
b <- 1
c1 <- 3.14
d <- -2.718

typeof(a)
typeof(b)
typeof(c1)
typeof(d)

    [1] "integer"
[1] "double"
[1] "double"
[1] "double"
    • 整数这个东西我们在自己手写代码时是很少见的，大家有的时候见到一个数字后面有个 L，就知道它是一个整数就可以了
    • 但是，整数会在其他地方悄悄出现：比如 1:5 这样的整数序列是整数；后面读入数据时，数据框中显示为 <int> 的列就是整数列，而显示为 <dbl> 的列就是双精度数列；用 n()、nrow() 等函数数出来的个数也是整数
    • 在日常的数据分析中，整数和双精度数的区别基本不影响计算，大家知道它们是两种不同的存储方式就可以了

    (b) 算数运算符¶

    整数与双精度数是支持使用基本的算数运算符进行运算的：

    • 基本的算数运算符包括：

      • 加法（+）
      • 减法（-）
      • 乘法（*）
      • 除法（/）
      • 取模（%%）：求余数
      • 整除（%/%）：求商的整数部分
      • 乘方（^）
      • 正号（+）
      • 负号（-）

    • 注意，R 中运算符之间是讲究优先级的：

      • 乘方的优先级最高
      • 其次是取模与整除（%%、%/%）
      • 然后是乘法和除法
      • 最后是加法和减法

    • 如果想要强调某个运算的优先级，我们可以使用括号来改变默认的优先级

    • 我们来看以下一些运算结果：

    1 + 2 * 3
(1 + 2) * 3
2^3 + 4
2^(3 + 4)
-3 + 5
+3 - 5
7 %% 3
7 %/% 3

    [1] 7
[1] 9
[1] 12
[1] 128
[1] 2
[1] -2
[1] 1
[1] 2
    • 其中 7 %% 3 表示 7 除以 3 的余数，结果是 1；7 %/% 3 表示 7 除以 3 的商的整数部分，结果是 2
    • 有一个容易出错的地方：负号的优先级比乘方低，所以 -2^2 的结果是 -4（先算 2^2 再取负），而 (-2)^2 的结果才是 4
    -2^2
(-2)^2

    [1] -4
[1] 4

    (c) 运算函数¶

    除了基本的算数运算符之外，R 还提供了很多内置的运算函数来进行各种各样的数学运算：

    • 例如：

      • sqrt(x)：计算 x 的平方根
      • log(x)：计算 x 的自然对数
      • log(x, base)：计算 x 的以 base 为底的对数
      • log10(x)：计算 x 的以 10 为底的对数
      • log2(x)：计算 x 的以 2 为底的对数
      • exp(x)：计算 e 的 x 次幂
      • abs(x)：计算 x 的绝对值
      • round(x, digits)：将 x 四舍五入到指定的小数位数
      • ceiling(x)：向上取整，返回大于或等于 x 的最小整数（例如 ceiling(3.2) 返回 4，ceiling(-3.2) 返回 -3）
      • floor(x)：向下取整，返回小于或等于 x 的最大整数（例如 floor(3.8) 返回 3，floor(-3.8) 返回 -4）
      • trunc(x)：截断，返回 x 的整数部分，不是四舍五入（例如 trunc(3.8) 返回 3，trunc(-3.8) 返回 -3）

    • 我们在以下的代码中来看看这些函数的使用示例：

    sqrt(16)
log(10)
log(100, base = 10)
log10(1000)
log2(8)
exp(1)
abs(-5)
round(3.14159, digits = 2)
ceiling(3.2)
floor(3.8)
trunc(3.8)

    [1] 4
[1] 2.302585
[1] 2
[1] 3
[1] 3
[1] 2.718282
[1] 5
[1] 3.14
[1] 4
[1] 3
[1] 3

    事实上，R 中还内置了大量的科学计算函数：

    • 例如三角函数与排列组合函数等等，但是商业分析情境下使用的比较少，我们这里就不展开介绍了
    • 这些函数和功能是不需要导入任何包就可以直接使用的
    • 这点也是 R 语言的一个优势了（相比于 Python 中很多数学函数需要导入额外的库），因此 R 会被很多学习者喜欢使用

    (d) 特殊的数值：Inf 与 NaN¶

    在数值运算中，有时会出现一些特殊的结果：

    • Inf 和 -Inf：表示正无穷和负无穷，比如一个非零的数除以 0 的时候就会得到它们
    • NaN：全称 Not a Number，表示"不是一个数"，比如 0 除以 0 的时候就会得到它
    1 / 0
-1 / 0
0 / 0

    [1] Inf
[1] -Inf
[1] NaN
    • R 在遇到除以零的时候不会报错，而是返回这些特殊值。这在数据分析中需要特别留意，比如计算增长率时，如果基期的值是 0，就会算出 Inf 或者 NaN
    • 我们可以用 is.infinite()、is.nan()、is.finite() 来检查它们

    另外还有一个需要注意的地方：计算机存储小数的时候是有精度限制的，所以有些看起来应该相等的小数，比较的时候却不相等：

    0.1 + 0.2 == 0.3
isTRUE(all.equal(0.1 + 0.2, 0.3))

    [1] FALSE
[1] TRUE
    • 这是所有编程语言都存在的现象，我们不需要深究原因，只要记住：不要直接用 == 去比较两个计算出来的小数，需要比较的时候可以使用 all.equal()

    2. 逻辑型（logical）¶

    (1) 逻辑型数据的定义¶

    逻辑型数据是 R 中用来表达是与否的数据类型，也叫布尔值，只有两种取值：TRUE 和 FALSE（注意全部大写）

    • 比方说我们定义两个变量 x 和 y 为逻辑型：
    x <- TRUE
y <- FALSE

typeof(x)
typeof(y)

    [1] "logical"
[1] "logical"
    • 逻辑型数据在 R 中是非常常见的，尤其是在条件判断和数据筛选中，我们会经常使用逻辑型数据来表达条件的真假
    • 虽然 R 中有 T 和 F 这两个简写，但是不推荐使用，因为它们其实是普通的变量，是可以被修改的，我们统一写成完整的 TRUE 和 FALSE

    逻辑型和数值型之间有着密切的联系：

    • 在 R 中，逻辑型数据可以被当作数值参与运算，TRUE 的数值是 1，而 FALSE 的数值是 0
    • 例如我们尝试运行以下代码：
    TRUE + TRUE
TRUE + FALSE
FALSE + FALSE
TRUE + 1
TRUE * 5
FALSE + 1

    [1] 2
[1] 1
[1] 0
[1] 2
[1] 5
[1] 1
    • 这个特点在数据分析中非常有用：对一组逻辑值求和，就可以得到 TRUE 的个数，求平均，就可以得到 TRUE 的比例（我们在 2.5 节中会看到具体的例子）
    • 但是要注意，这并不意味着逻辑型是数值型的一种，它们是两种不同的类型，比如 is.numeric(TRUE) 的结果是 FALSE

    (2) 比较运算符¶

    逻辑型数据经常是由比较运算符来产生的

    • R 中的比较运算符包括：

      • 等于 （==）
      • 不等于（!=）
      • 大于（>）
      • 小于（<）
      • 大于等于（>=）
      • 小于等于（<=）

    • 例如我们可以运行以下代码来看看这些比较运算符的使用示例：

    1 == 1
1 == 2
1 != 2
3 > 2
3 < 2
3 >= 3
2 <= 3

    [1] TRUE
[1] FALSE
[1] TRUE
[1] TRUE
[1] FALSE
[1] TRUE
[1] TRUE
    • 注意，判断相等要用两个等号 ==，一个等号 = 是赋值/传参数，千万不要混淆
    • 比较运算符也可以用来比较字符，比如 "apple" == "apple" 的结果是 TRUE，注意字符是区分大小写的，"apple" == "Apple" 的结果是 FALSE
    • 还有一个很常用的运算符是 %in%，它用来判断左边的值是否在右边的集合当中：
    5 %in% c(1, 5, 9)
"b" %in% c("a", "c")

    [1] TRUE
[1] FALSE

    (3) 逻辑运算符¶

    我们还可以使用逻辑运算符来连接多个逻辑表达式

    • R 中的逻辑运算符包括：

      • 与（&）：表示两个表达式都为 TRUE 时结果才为 TRUE
      • 或（|）：表示两个表达式中至少有一个为 TRUE 时结果就为 TRUE
      • 非（!）：表示取反，如果表达式为 TRUE，结果就为 FALSE；如果表达式为 FALSE，结果就为 TRUE

    • 并且，逻辑运算也是有优先级的，总得来说，括号的优先级最高，其次是非（!），然后是与（&），最后是或（|）。如果记不清，就直接用括号把想先算的部分括起来

    • 例如我们可以运行以下代码来看看这些逻辑运算符的使用示例：

    1 < 5 & 2 > 1
1 < 5 | 2 > 3
!(1 < 5)
!(2 > 3)
(1 < 5 & 2 > 1) | (3 < 2)
(1 < 5 & 2 > 1) & (3 < 2)

    [1] TRUE
[1] TRUE
[1] FALSE
[1] TRUE
[1] TRUE
[1] FALSE
    • 另外，R 中还有 && 和 || 这两个双符号的版本，它们只能用于单个逻辑值，而我们在数据筛选中处理的是一整列的逻辑值，所以后面基本只会用到单符号的 & 和 |

    3. 缺失值（NA）¶

    (1) 缺失值的定义¶

    在 R 中，缺失值（NA，Not Available）表示数据中没有值或者值不可用

    • 这里注意一个易混淆的点：NA 不是 0，也不是空字符串 ""，它是一个特殊的值，表示缺失值
    • 现实中的数据几乎都会有缺失值，比如问卷中被跳过的问题、没有记录下来的销售额等等，所以学会处理 NA 是数据分析中非常重要的一环
    • 例如我们可以定义一个变量 z 为 NA，来看看它的类型：
    z <- NA
typeof(z)

    [1] "logical"
    • 这里为什么 NA 的类型是逻辑型呢？这个其实算是 R 语言的不同于其他编程语言的一个特点了，单独写的 NA 是一个特殊的逻辑值
    • 但是当 NA 出现在数值向量里的时候，它就会变成对应类型的缺失值，比如 c(1, NA) 的类型是 "double"，大家不需要担心这个细节

    (2) 缺失值的运算结果¶

    在 R 中，任何与 NA 进行的算数运算与比较运算都会得到 NA

    • 因为 NA 表示缺失值，我们无法确定它的具体数值，所以任何与 NA 相关的计算结果都是未知的，也就是 NA
    • 例如我们可以运行以下代码来看看 NA 的运算结果：
    NA + 1
NA * 5
log(NA)
NA == NA
NA > 0

    [1] NA
[1] NA
[1] NA
[1] NA
[1] NA

    然而，在 R 中，NA 的逻辑运算结果是有些奇怪的：

    • 我们首先看一下 NA 逻辑运算的结论：

      • NA & TRUE 的结果是 NA
      • NA & FALSE 的结果是 FALSE - 如果已经确定其中一个表达式为 FALSE，那么 FALSE 与任何表达式的逻辑与结果都是 FALSE，所以 NA & FALSE 的结果是 FALSE
      • NA | TRUE 的结果是 TRUE - 如果已经确定其中一个表达式为 TRUE，那么 TRUE 与任何表达式的逻辑或结果都是 TRUE，所以 NA | TRUE 的结果是 TRUE
      • NA | FALSE 的结果是 NA
      • !NA 的结果是 NA
      • NA & NA 的结果是 NA
      • NA | NA 的结果是 NA

    • 我们可以运行以下代码来看看这些逻辑运算的结果：

    NA & TRUE
NA & FALSE
NA | TRUE
NA | FALSE
!NA
NA & NA
NA | NA

    [1] NA
[1] FALSE
[1] TRUE
[1] NA
[1] NA
[1] NA
[1] NA

    (3) 缺失值的判断与处理¶

    既然 NA == NA 的结果是 NA，那我们怎么判断一个值是不是缺失值呢？答案是使用 is.na() 函数：

    is.na(NA)
is.na(5)
NA == NA

    [1] TRUE
[1] FALSE
[1] NA
    • 判断缺失值只能用 is.na()，不能用 == NA
    • is.na() 对一整列数据使用时，会对每个元素分别判断，返回一组逻辑值；结合前面讲的"对逻辑值求和就是数 TRUE 的个数"，我们就可以数出一列数据中有多少个缺失值（我们在 2.5 节会看到）

    另外，当数据中含有 NA 的时候，很多统计函数（如 sum()、mean()、max()）的结果也会变成 NA，因为只要有一个值未知，总和或者平均值也就未知了：

    sales <- c(10, NA, 30)
mean(sales)
mean(sales, na.rm = TRUE)

    [1] NA
[1] 20
    • 这时，我们可以给函数加上参数 na.rm = TRUE（remove NA 的缩写），意思是"计算时先把缺失值去掉"，这样就能得到有效数据的统计结果
    • 但是，去掉缺失值是一个需要谨慎的决定，缺失值为什么缺失、去掉之后会不会影响结论，都是需要分析师思考的问题，不能不加思考地直接使用 na.rm = TRUE

    最后，我们来区分一下 NA 和另一个容易混淆的值 NULL：

    • NA 表示"这里应该有一个值，但是缺失了"，它占一个位置
    • NULL 表示"什么都没有"，它不占位置，比如 length(NULL) 是 0，而 length(NA) 是 1
    • 我们在后面的课程中，会在函数的参数或者处理 JSON 数据的时候遇到 NULL，这里大家有个印象就可以了

    4. 字符型（character）¶

    字符型数据，就相当于是 R 中的文字数据，它是由一系列字符组成的文本数据。

    • 在 R 中，字符型数据是由双引号 " 或单引号 ' 包裹起来的文本数据：

    • 例如我们可以定义以下几个变量来看看它们的类型：

    str1 <- "Hello, World!"
str2 <- 'R is great!'
typeof(str1)
typeof(str2)

    [1] "character"
[1] "character"
    • 加了引号的内容才是字符：5 是数值，而 "5" 是字符，"5" + 1 会报错，因为文字是不能做加法的
    • 反过来，不加引号的文字会被 R 当成变量名，比如写 Hello 而不是 "Hello"，R 会去找一个叫 Hello 的变量，找不到就会报 object not found 的错误，这是初学者最常见的错误之一

    关于字符型数据，我们在后续的课程中会详细介绍它的相关操作，这里我们先简单介绍两个最常用的函数：

    nchar("Hello")
paste("Hello", "World")
paste0("Hello", "World")

    [1] 5
[1] "Hello World"
[1] "HelloWorld"
    • nchar() 用来计算字符串的长度
    • paste() 用来把多个字符串拼接在一起，默认用空格连接，paste0() 则是不用任何分隔符直接连接

    5. 因子型（factor）¶

    因子型数据用来表示类别数据，比如性别、产品等级、地区等等，它是在字符型数据的基础上，给每一个类别赋予了一个固定的"水平"

    • 我们先看一个例子，假设有 6 位顾客购买的 T 恤尺码：
    size <- factor(c("S", "L", "M", "S", "S", "M"))
size

    [1] S L M S S M
Levels: L M S
    • 因子的所有可能取值叫做水平（levels），可以用 levels() 函数查看
    • 如果创建因子时不指定水平，R 会按字母顺序自动排列，这就是为什么上面的水平顺序是 L M S，而不是我们直觉中的 S M L
    • 因子的底层其实是用整数来存储的（每个整数对应一个水平），所以不要把因子当作数值来用，也不要随便把因子转成数值

    在数据分析中，因子最重要的作用是控制类别的顺序，比如画图时，坐标轴上类别的排列顺序就是由因子的水平顺序决定的

    • 如果类别之间有自然的顺序（比如尺码 S < M < L，或者"一等奖 > 二等奖 > 三等奖"），我们可以在 factor() 函数中用 levels 参数指定水平的顺序，并设置 ordered = TRUE 创建有序因子
    • 而字符型数据只是简单的文本数据，默认只能按字母（或笔画）顺序排列，无法表达这种我们自定义的顺序关系
    size <- factor(c("S", "L", "M", "S", "S", "M"), levels = c("S", "M", "L"), ordered = TRUE)
size

    [1] S L M S S M
Levels: S < M < L
    • 我们可以看到，水平的顺序变成了 S < M < L，而且有序因子之间是可以比较大小的：
    size[1] < size[2]

    [1] TRUE
    • 再来看看我们原来的例子，把"一等奖"、"二等奖"、"三等奖"这三个类别转换成有序因子：

    prizes <- factor(c("一等奖", "二等奖", "三等奖"), levels = c("三等奖", "二等奖", "一等奖"), ordered = TRUE)
prizes

    [1] 一等奖 二等奖 三等奖
Levels: 三等奖 < 二等奖 < 一等奖

    • 总结一下，因子有两种：普通因子只有水平，没有大小顺序；有序因子（ordered = TRUE）的水平是有大小顺序的

    关于因子型数据，我们在后续的课程中会详细介绍它的相关操作，这里我们先简单介绍一下。

    6. 日期型（Date）¶

    日期型数据是在 R 中用来表示日期和时间的数据类型，R 中有两种常用的日期时间类型：

    • Date：只包含年、月、日的日期，没有时区的概念
    • POSIXct：包含年、月、日、时、分、秒的日期时间，具体到秒（以及秒的小数部分）

    在 R 中，我们可以使用 as.Date() 函数与 as.POSIXct() 函数把文本转换成日期型数据：

    • as.Date() 函数用来创建只包含年、月、日的日期型数据
    • as.POSIXct() 函数用来创建包含年、月、日、时、分、秒的日期时间型数据，如果不指定时区，则使用系统的本地时区
    • 例如我们可以创建以下几个日期型数据来看看它们的类型：
    date1 <- as.Date("2024-01-01")
date2 <- as.Date("2024-06-30 09:20:15")
date3 <- as.POSIXct("2024-06-30 09:20:15")
date4 <- as.POSIXct("2024-12-31 08:46:30.123")

date1
date2
date3
date4

typeof(date1)
typeof(date2)
typeof(date3)
typeof(date4)

    [1] "2024-01-01"
[1] "2024-06-30"
[1] "2024-06-30 09:20:15 AEST"
[1] "2024-12-31 08:46:30 AEDT"
[1] "double"
[1] "double"
[1] "double"
[1] "double"

    在上面的运行结果中，我们可以看到：

    • as.Date() 函数只具体到日，如果输入的字符串中包含时、分、秒部分，那么这些部分会被忽略
    • as.POSIXct() 函数具体到秒，R 默认只显示到秒，输入字符串中的毫秒部分虽然被保留了下来，但是在默认设置下不会显示出来（时区缩写如 AEST 会因电脑的时区设置不同而不同）

    在 R 中，如果想要显示毫秒，我们需要一个全局设置 options(digits.secs = 3)

    • 这个设置会让 R 语言在显示日期时间数据时保留毫秒部分
    • 并且这个设置会影响到当前 R 会话中的所有日期时间数据的显示方式
    options(digits.secs = 3)
date5 <- as.POSIXct("2024-12-31 08:46:30.123")
date5

    [1] "2024-12-31 08:46:30.123 AEDT"
    • 如果想要取消这个设置，我们可以把 digits.secs 的值设置回默认值 0：
    options(digits.secs = 0)
date6 <- as.POSIXct("2024-12-31 08:46:30.123")
date6

    [1] "2024-12-31 08:46:30 AEDT"

    还有一个比较重要的注意事项：

    • 为什么 as.Date() 和 as.POSIXct() 函数创建的日期型数据的类型都是 "double" 呢？

    • 这是因为在 R 中，日期型数据其实是以一个数字来存储的，这个数字是从 1970-01-01 开始数起的：

      • Date 存储的是从 1970-01-01 到这个日期的天数
      • POSIXct 存储的是从 1970-01-01 00:00:00 到这个时刻的秒数

    • 所以它们的底层数据类型是 "double"，而不是我们直观上理解的 "Date" 类型

    • 我们可以把日期转换成数字来验证：
    as.numeric(as.Date("2024-01-01"))

    [1] 19723
    • 正因为日期底层是数字，所以日期是可以直接做加减法的：
    date_start <- as.Date("2024-01-01")
date_end <- as.Date("2024-03-15")

date_end - date_start
date_start + 30

    Time difference of 74 days
[1] "2024-01-31"

    最后，as.Date() 默认只认识 年-月-日（如 "2024-06-30"）或 年/月/日 这两种格式的文本，如果文本的格式不同，需要用 format 参数告诉 R 这段文本的格式：

    as.Date("30/06/2024", format = "%d/%m/%Y")

    [1] "2024-06-30"
    • 其中 %d 表示日、%m 表示月、%Y 表示四位数的年份
    • 这种写法比较繁琐，在后续的课程中，我们会学习更方便的 lubridate 包，比如 ymd("2024-06-30")、dmy("30/06/2024")，来处理各种各样的日期格式

    7. 查看与转换数据类型¶

    (1) 查看数据类型：class() 与 typeof()¶

    到目前为止，我们一直用 typeof() 来查看数据类型，它告诉我们的是数据底层的存储方式。除此之外，R 还有一个 class() 函数，它告诉我们的是数据在使用时被当作什么类型：

    class(1L)
class(1)
class("a")
class(TRUE)
class(as.Date("2024-01-01"))
class(factor("a"))

    [1] "integer"
[1] "numeric"
[1] "character"
[1] "logical"
[1] "Date"
[1] "factor"
    • 可以看到，日期的 typeof() 是 "double"，而 class() 是 "Date"；因子的 typeof() 是 "integer"，class() 是 "factor"
    • 日常工作中我们更常用 class()，因为它更符合直觉；typeof() 则帮助我们理解数据底层是怎么存储的
    • 我们在后面还会学习 glimpse() 这样的函数，它可以一次性查看数据框中每一列的类型

    (2) 转换数据类型¶

    有时候，数据读入 R 之后类型不是我们想要的，比如数字被读成了文本，这时就需要进行类型转换。R 中类型转换的函数都以 as. 开头：

    • as.numeric()：转换成数值型
    • as.integer()：转换成整数型
    • as.character()：转换成字符型
    • as.logical()：转换成逻辑型
    • as.factor()：转换成因子型
    • as.Date()：转换成日期型
    as.numeric("3.14")
as.character(42)
as.integer(3.9)
as.logical(c(0, 1, 2))

    [1] 3.14
[1] "42"
[1] 3
[1] FALSE  TRUE  TRUE
    • 注意 as.integer(3.9) 的结果是 3，它是直接截断小数部分，而不是四舍五入
    • 对于逻辑型，0 会被转换成 FALSE，其他所有非零的数都会被转换成 TRUE

    如果转换不成功，R 不会报错，而是给出一个警告，并把结果变成 NA：

    as.numeric("abc")

    [1] NA
Warning message:
NAs introduced by coercion
    • 看到 NAs introduced by coercion 这个警告，说明有一些值没能成功转换，需要回去检查数据，比如数字中是否夹杂了 $、, 或其他文字

    最后还有一个需要特别小心的地方：不要直接用 as.numeric() 转换因子。因子的底层是整数编码，直接转换得到的是编码，而不是它看起来的数字：

    f <- factor(c("10", "20", "10"))
as.numeric(f)
as.numeric(as.character(f))

    [1] 1 2 1
[1] 10 20 10
    • 正确的做法是先用 as.character() 转换成字符，再用 as.numeric() 转换成数值
