    Class 6.4 - 面板数据¶

    1. 面板数据的定义¶

    面板数据是横截面数据与时间序列数据的结合，既有多个个体，又有多个时间点的数据：

    • 既可以将某一观测值与同一时间点上的其他观测值进行横向比较，也能与该观测值自身的历史数据进行纵向对比
    • 这其实是一种视野拓宽，避免了单纯横截面数据或时间序列数据的局限性

    • 在更深入的分析（比如回归分析）中，面板数据还有一个重要的优势，就是可以用固定效应来排除一些干扰因素，这里我们只介绍直觉：

      • 时间固定效应：排除"所有公司在同一时期都会受到的影响"，比如 2008 年的金融危机、新冠疫情，做法相当于把每家公司和同一时期的平均水平去比较
      • 个体固定效应：排除"每家公司自身不随时间变化的特征"，比如它所在行业本身的盈利能力，做法相当于把一家公司和它自己的过去去比较（拿苹果和苹果比，而不是拿苹果和一家咖啡店比）

    4. 面板数据的分组计算¶

    (1) 面板数据分组计算的概念¶

    我们之前介绍到的分组计算的概念，在面板数据中尤其重要

    • 比方说，如果我们想要计算每天所有股票的收益率之和，那就要按照日期进行分组计算
    • 比方说，如果我们想要计算每只股票的总收益，那就要按照股票进行分组计算

    下面这个简单的面板数据展示了按时间分组和按对象分组的区别：

    在金融数据的情景下：

    • 如果我们计算收益率，计算方法是本行价格减去上一行价格，再除以上一行价格
    • 但是，这个操作必须要在同一只股票的时间序列数据中进行，不能跨股票进行计算，否则就会得到错误的结果
    • 比方说下表中，计算股票 B 的收益率是不能使用股票 A 的价格数据的：
    date ticker price price_lag return
    2025-01-02 A 100 NA NA
    2025-01-03 A 105 100 (105 - 100) / 100
    2025-01-04 A 110 105 (110 - 105) / 105
    2025-01-02 B 200 NA NA
    2025-01-03 B 210 200 (210 - 200) / 200
    2025-01-04 B 220 210 (220 - 210) / 210

    如果我们忘记分组，会发生什么呢？我们来看一个例子：

    all_stocks |>
    arrange(ticker, date) |>
    mutate(Return_wrong = Adjusted / lag(Adjusted) - 1) |>
    filter(ticker == "AMZN") |>
    slice_head(n = 2) |>
    select(date, ticker, Adjusted, Return_wrong)

    | date <date> | ticker <chr> | Adjusted <dbl> | Return_wrong <dbl> |
|-------------|--------------|----------------|--------------------|
| 2025-01-02  | AMZN         | 220.22         | -0.26103153        |
| 2025-01-03  | AMZN         | 224.19         | 0.01802743         |
    • 在 AMZN 的第一行，lag(Adjusted) 取到的是上一行的价格，也就是 AAPL 最后一天的价格（298.01），所以算出来了一个 -26% 的"收益率"，这显然是错的，AMZN 的第一天本来应该是没有收益率（NA）的
    • 这种错误不会有任何报错或者警告，只会悄悄地让结果出错，所以对面板数据做跨行计算时，一定要先分组

    这里，我们就可以使用之前介绍过的 group_by() 和 mutate() 函数来实现这个分组计算：

    • 并且，在排序的时候，我们需要使用 arrange() 函数，并且设置 .by_group = TRUE 来确保我们是在每个分组内按照日期排序的
    • 除此之外，我们还可以使用 ungroup() 函数来取消分组，这样后续的计算就不会受到分组的影响了

    (2) 面板数据按对象分组¶

    首先，我们来按股票分组

    • 我们计算一下每只股票的收益率与累计收益率：
    all_stocks <- all_stocks |>
    group_by(ticker) |>
    arrange(date, .by_group = TRUE) |>
    mutate(
        Return   = Adjusted / lag(Adjusted) - 1,
        Cumret = cumprod(1 + coalesce(Return, 0)) - 1
    ) |>
    ungroup()

    (3) 面板数据按时间分组¶

    接着，我们再来看一个按照时间分组的例子

    • 我们来计算一下，每日的总收益率，以及每日收益率的累计，假设我们仓内每只股票的权重相等：
    pf_ew <- all_stocks |>
    group_by(date) |>
    summarise(
        ew_ret = mean(Return, na.rm = TRUE)
    ) |>
    arrange(date) |>
    mutate(
        ew_cumret = cumprod(1 + coalesce(ew_ret, 0)) - 1
    )

    (4) 加权投资组合¶

    等权组合只是其中一种组合方式，另一种常见的方式是市值加权：市值越大的公司，在组合中的权重越大。

    • 回忆一下 6.2 节中，我们计算了这 5 家公司的市值 mktcap（保存在 top5 中），我们可以把它作为权重，先用 left_join() 把市值连接到面板数据上，再用 weighted.mean() 来计算每日的加权平均收益率：
    # 重新创建 6.2 节中的 top5，里面有这 5 家公司的市值
top5 <- read_csv("sp500_xs.csv") |>
    mutate(mktcap = prc * shrout) |>
    arrange(desc(mktcap)) |>
    slice_head(n = 5)

pf_vw <- all_stocks |>
    left_join(top5 |> select(ticker = tic, mktcap), by = join_by(ticker)) |>
    group_by(date) |>
    summarise(
        vw_ret = weighted.mean(Return, mktcap, na.rm = TRUE)
    ) |>
    arrange(date) |>
    mutate(
        vw_cumret = cumprod(1 + coalesce(vw_ret, 0)) - 1
    )

    • 在构建组合时，有一个非常重要的原则：权重只能使用在构建组合的那一刻已经知道的信息，如果使用了未来才知道的信息（比如用 2026 年的市值，去构建一个 2025 年的组合），就会产生"前视偏差"，让回测的结果好得不真实
    • 这里的代码对所有日期使用了同一组市值权重，同样意味着每天都把组合调整回这个权重（每天再平衡）
