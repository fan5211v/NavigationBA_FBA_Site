    Class 11.2 - 使用 API 获取数据¶

    1. API 基本介绍¶

    (1) API 的定义¶

    API 是应用程序接口（Application Program Interface）的缩写，是计算机和计算机程序之间建立"连接"的一套标准规则或程序：

    • 直白理解，API 就是使用程序来获取别的公司或组织的数据的，比方说用 R 代码、Python 代码等来获取数据，而不是直接下载 CSV 文件或 Excel 文件

    • 比方说 Twitter API，就是 Twitter 公司提供的，允许我们通过 Python 或 R 程序来将 Twitter 帖子下载到我们的计算机上进行分析

    • 事实上，Twitter 的 API 和 Twitter 的 APP 一样，都是从 Twitter 数据库调用数据：

      • 一篇帖子，如果被 Twitter APP 调用，这篇帖子就会出现在用户的手机上
      • 同一篇帖子，如果被 Twitter API 调用，这篇帖子就会出现在分析师的计算机上

    • 通过 API 我们可以调用各种各样的数据，但是 API 最常用的数据格式其实是 JSON：

      • 因为 JSON 不拘泥于严格的表格形式，可以包含层次结构和嵌套结构，适合表示复杂的数据关系
      • 同时 JSON 本质还是文本文件，占用空间小，易于传输和解析
    {
  "id": 12345,
  "text": "今天去海边玩耍了",
  "user": {
    "id": 67890,
    "name": "张三"
  },
  "created_at": "2024-01-01T12:00:00Z",
  "comments": [
    {
      "id": 54321,
      "text": "海滩人多吗？",
      "user": {
        "id": 98765,
        "name": "李四"
      },
      "created_at": "2024-01-02T08:00:00Z"
    },
    {
      "id": 54322,
      "text": "我也想去！",
      "user": {
        "id": 87654,
        "name": "王五"
      },
      "created_at": "2024-01-02T09:00:00Z"
    }
  ]
}

    API 的运行逻辑是：

    • 当你向 API 发送一个请求时，API 会处理这个请求并返回一个响应
    • 如果请求数据成功，响应将告诉你请求成功，并返回你请求的数据
    • 如果请求失败，响应将告诉你请求失败，以及失败的原因，例如，权限不足、请求格式错误、服务器错误等

    我们可以把这个过程想象成在图书馆向图书管理员请求一本书：

    • 在图书馆，有时候，你无法直接去书架找书
    • 在这种情况下，你可以向图书管理员提交请求，管理员会帮你从书架上取书
    图书馆类比 API 对应
    你 数据用户
    图书管理员 API
    只有员工可进入的区域 你无法直接访问的内部系统或数据库
    索书请求 你的程序发送给 API 的消息
    管理员取回的书 API 提供的数据或服务

    (2) API 的优势¶

    如今，许多数据提供者将 API 设置为向数据用户提供数据的首选方式，有以下几个优势：

    • 受控访问：API 允许数据提供者只提供部分数据或功能，而不是给用户完全访问所有数据，有助于保护敏感数据和系统完整性
    • 标准化：通过提供标准化的数据访问方式，降低成本，因为用户无需自己开发复杂的数据获取程序
    • 创新和生态系统增长：API 允许第三方开发者直接在获取到的数据上构建应用程序和服务，促进创新和生态系统的增长，例如 Uber 调用了 Google Maps API，这样 Uber 的开发就可以专注于构建自己的核心功能，而不是重新开发地图功能
    • 使用追踪和管理：API 可以方便监控谁在使用数据以及使用频率，可以基于使用量进行收费，或者限制访问以防止滥用

    (3) API 的工作流程¶

    尽管每个 API 在许多方面可能差异很大，但基本的工作流程通常遵循以下步骤：

    1. 阅读 API 文档：这个是数据提供方给的 API 说明书，告诉你这个 API 能获取到什么数据，应该怎么用
    2. 获取 API 密钥：这个相当于账户密码，只有使用账户密码登录后才能获取数据提供方给的数据
    3. 发起 API 请求：通过代码告诉 API，我们想要什么样的数据
    4. 解析 JSON 响应：我们上面也提到了，API 通常返回的是 JSON 格式的数据
    5. 转化为可分析的表格：也就是我们上一章把 JSON 文件转化为表格的过程

    2. 在 R 中使用 API 获取数据¶

    本节我们以一个模拟的音乐数据库的 API 为例，来演示如何使用 API 获取数据并进行分析：

    • 这个模拟的音乐数据库包含了各种音乐相关的数据，例如歌曲、艺术家、专辑等，我们将通过 API 来获取这些数据
    • 这个 API 是一个教学目的的模拟 API，数据并不是真实的，只作演示

    API 通常返回结构化传输数据，而不是可直接分析的表格。收到 API 响应后，我们需要：

    1. 收到 API 响应并将其解析为 JSON 文本
    2. 将 JSON 文本解析为 R 列表
    3. 将 R 列表矩形化为 R 表格
    4. 清洗为整洁表格
    5. 存储为数据库表

    事实上，在这 5 个步骤中：

    • 2-5 其实都是我们上一节讲解 JSON 文件时已经介绍过的内容了
    • 本节的新内容主要是第 1 步：如何发起 API 请求并获取响应，以及API 响应的结构和内容是什么样的

    (1) 获取并解析 API 响应¶

    从 API 调取数据使用的 R 包主要是 httr，帮助我们与 API 通信，获取响应

    • 这个包中的 GET() 函数用于发起 GET 请求
    • 我们需要在 GET() 函数中指定目标网址和查询参数，来告诉 API 我们想要什么样的数据
    # 加载必要的 R 包
library(httr)
library(jsonlite)
library(tidyverse)

# 定义 API 的基础 URL
api_url <- "https://api.music-to-scrape.org"

# 使用 GET() 函数发起 API 请求，获取热门曲目数据
response <- GET(
  # 使用 paste0() 函数构建完整的 URL，指定我们想要获取热门曲目的数据
  url = paste0(api_url, "/charts/top-tracks"),
  # 通过 query 参数传递查询参数，告诉 API 我们想要特定时间窗口的热门曲目数据，并且限制返回的结果数量为 5 条
  query = list(
    unixtimestamp = as.integer(as.POSIXct("2026-05-01", tz = "UTC")),
    limit = 5
    )
  )

    这里：

    • 原始的网址是 https://api.music-to-scrape.org
    • 然而真正的数据却不在这里，我们通过在 URL 后面添加 /charts/top-tracks 来指定我们想要获取热门曲目的数据
    • 因此，真正的 URL 是 https://api.music-to-scrape.org/charts/top-tracks
    • 我们可以将 https://api.music-to-scrape.org 看作是基础目录，而我们想要获取的数据就像是这个目录下的一个文件夹或文件，我们通过在 URL 后面添加路径来指定我们想要获取的数据

    我们使用 GET() 函数获得的 response 对象就是 API 的响应：

    • 如果请求成功，response 对象将包含成功的状态码（主要是 200），以及我们请求的数据
    • 如果请求失败，response 对象将包含错误的状态码（包括 404、500 等），以及错误信息

    之后，我们可以通过一系列检查来了解这个响应对象的结构和内容：

    • 我们可以使用 status_code() 函数检查响应的状态码：
    status_code(response)

    [1] 200

    • 返回 200 表示请求成功，我们可以继续处理响应中的数据了

    • 也可以使用 http_type() 函数查看响应的数据格式：

    http_type(response)

    [1] "application/json"

    • 返回 "application/json" 表示我们收到了熟悉的 JSON 格式

    • 我们还可以查看响应的元数据，也就是本次响应的一些基本信息：

    headers(response)

    $server
    'nginx/1.18.0 (Ubuntu)'
$date
    'Sat, 30 May 2026 10:34:44 GMT'
$content-type
    'application/json'
$content-length
    '389'
$connection
    'keep-alive'

    • 这些元数据表示：

      • 服务器使用的是 nginx 1.18.0
      • 响应的时间是 2026 年 5 月 30 日
      • 响应的数据类型是 JSON
      • 响应的数据长度是 389 字节
      • 连接状态是保持连接

    (2) 解析响应为 JSON 文本¶

    之后，我们使用 content() 函数将响应中的 JSON 数据提取出来，并解析为文本：

    json_text <- content(response, as = "text", encoding = "UTF-8")
json_text

    • 可以看到，这个文本和我们上一章的 JSON 文件的内容是一样的
    • 使用键值对来表示数据，并且有层层嵌套的结构

    (3) 解析 JSON 文本为 R 列表并进行后续处理¶

    接下来，我们使用 fromJSON() 函数，将原始 JSON 文本手动解析为嵌套 R 列表：

    top_tracks_list <- fromJSON(json_text, simplifyVector = FALSE)
    • 验证解析结果是一个列表：
    typeof(top_tracks_list)

    [1] "list"
    • 查看顶层键：
    names(top_tracks_list)

    [1] "unix_start"  "unix_end"  "chart"

    接着，我们可以查看列表结构：

    • 这里是将列表转为字符串，并且指定只显示前两层
    • 列表如果生硬地转为字符串，会显示所有层级的内容，这样就会非常冗长，所以我们指定只显示前两层
    str(top_tracks_list, max.level = 2)

    List of 3
 $ unix_start: int 1777593600
 $ unix_end  : int 1780137283
 $ chart     :List of 5
  ..$ :List of 3
  ..$ :List of 3
  ..$ :List of 3
  ..$ :List of 3
  ..$ :List of 3

    • 结果显示：

      • chart 键对应的值是一个包含 5 个元素的列表
      • 每个元素又是一个包含 3 个键值对的列表，分别是 name、artist 和 plays

    • 因此我们可以尝试查看 chart 键对应的第一个元素：

    top_tracks_list$chart[[1]]

    $name
    'Call Me'
$artist
    'Mint Condition'
$plays
    37

    事实上，我们可以看到，仅仅看热门歌曲，数据结构就已经很清晰了：

    • 每个歌曲都是一个列表
    • 并且包含共同的键：name、artist、plays
    • 因此，把这些歌曲放在一个表格中，每行对应一首歌，每列对应一个属性，就可以很方便地进行分析了

    因此，我们将 chart 包装进 tibble，并直接用 unnest_wider() 展开：

    top_tracks_tbl <- tibble(record = top_tracks_list$chart)

top_tracks_raw <- top_tracks_tbl |>
  unnest_wider(record)

top_tracks_raw

    top_tracks_raw |>
  count(artist, sort = TRUE)

  summarise(sum_plays = sum(plays))

    3. 更多 API 请求的例子¶

    我们目前已经成功地发起了一个 API 请求，并且将返回的 JSON 数据转化为了一个整洁的表格，接下来我们可以尝试更多的 API 请求：

    (1) 更改查询参数¶

    我们之前查看了一个时间窗口的热门曲目，现在我们请求一个更早年份的窗口：

    response_week_1 <-
  GET(
    url = paste0(api_url, "/charts/top-tracks"),
    query = list(
      unixtimestamp = as.integer(as.POSIXct("2025-01-01", tz = "UTC")),
      limit = 5
    )
  )

tracks_week_1_list <- content(response_week_1, as = "text", encoding = "UTF-8") |>
  fromJSON(simplifyVector = FALSE)

tracks_week_1_raw <- tibble(record = tracks_week_1_list$chart) |>
  unnest_wider(record)

    (2) 更改端点¶

    之前我们提到过：

    • 基础网址 https://api.music-to-scrape.org 就像一个目录，我们通过在 URL 后面添加路径来指定我们想要获取的数据
    • 之前我们添加了 /charts/top-tracks 来获取热门曲目的数据
    • 现在我们可以尝试添加不同的路径来获取不同类型的数据，例如，添加 /charts/top-artists 来获取热门艺术家的数据：
    response_artists <- GET(url = paste0(api_url, "/charts/top-artists"))

top_artists_list <- content(response_artists, as = "text", encoding = "UTF-8") |>
  fromJSON(simplifyVector = FALSE)

top_artists_raw <- tibble(record = top_artists_list$chart) |>
  unnest_wider(record)
