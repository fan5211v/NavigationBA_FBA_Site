    Topic 10.3 - 数据存储：JSON¶

    1. JSON 数据的概念¶

    (1) JSON 数据简介¶

    JSON 的全称是 JavaScript Object Notation，是一种专为存储结构化数据设计的文本格式

    • JSON 最大的特点就是支持多层嵌套结构，可以将相关的数据存储在一个对象中，而不需要重复字段

    • 嵌套结构其实是为了解决 Excel 或 CSV 这类表格数据的局限性：

      • 表格都是有行有列的，这就限制了所有观测都必须共享相同的列，并且一行一列的一个单元格内只能存储一个值
      • 但现实中的数据往往具有层次结构
      • 比方说网购这个情景，如果我们用一行代表一个商品的信息，那么商品的名称、分类、价格这些信息倒是能放在一个单元格里，但是评论就不太好放了
      • 每个商品可能有不同数量的评论，每条评论又包含评论人、评分、评论内容等多个属性，这些信息很难用表格来存储

    • 这时候我们就需要一种更加灵活的数据格式来存储这些信息

    JSON 就是这样一种格式：

    • JSON 使用键值对来存储数据
    • 键指的是数据的属性名称，通常是字符串，例如 "item_id"、"title"、"seller" 等
    • 值指的是数据的具体内容，可以是各种各样的数据类型，包括字符串、数字、列表、甚至是另一个 JSON 对象

    • 有些属性是单层结构的键值对，例如 item_id、title、category 等

    • 但有些属性是嵌套结构的，例如：

      • seller 嵌套了一个 JSON 对象

    大家看到这个结构可以感受到：

    • JSON 的记录方式是很灵活的，可以存储非常复杂的数据结构
    • 但是有个问题就是这种数据处理起来是不太方便的
    • 因此我们后续的任务还是想把它尽可能地转化为我们熟悉的表格形式，这样不管是行操作还是列操作都更方便一些
    • 这就是我们后续要介绍的数据矩形化的概念

    2. 在 R 中处理 JSON 数据¶

    (1) 读取 JSON 文件¶

    将 JSON 文件读入 R 中，使用的是 jsonlite 包中的 read_json() 函数：

    library(jsonlite)

auctions_nested <- read_json("ebay_auctions.json")

typeof(auctions_nested)

    [1] "list"

    可以看到，auctions_nested 读取进来以后是一个拍卖记录的列表

    • 事实上，它是一个 R 中列表套列表的结构：

      • 最外层的 JSON 数组是一个 R 列表
      • 这个 JSON 数组中的每个元素，在 R 中又是一个列表，代表一条拍卖记录
      • 在每条拍卖记录的列表中，又有一些键对应的值是单层结构的，例如 item_id、title 等，这些键对应的值在 R 中就是单个的值
      • 但也有一些键对应的值是嵌套结构的，例如 seller 和 bids，在 R 中它们又是一个列表，分别代表卖家信息和出价历史

    • 大家不要试着把这个对象打印在控制台，因为它包含了上千条拍卖记录，打印出来会很占用资源的

    • 我们可以做的是打印其中的一个拍卖记录

    在 R 中，列表的访问方式是：

    • 用双中括号 [[ ]] 来访问顺序元素
    • 用美元符号 $ 来访问命名元素

    • 大家其实可以感受到，这种层级结构虽然很灵活，但在 R 中处理起来是非常麻烦的
    • 因此我们后续的任务就是要把它转化为我们熟悉的表格形式

    (2) 将列表包装成 Tibble¶

    将 R 中的列表转换为 tibble，其实就是将这个列表的嵌套结构层层拆解的过程

    • 在将列表生硬地转换为 tibble 时，整个 tibble 只有一列，列名是 record，整个列表都塞到了一个单元格内
    • 之后，我们就要将这个列表的层次结构逐层拆解
    • 由于列表是嵌套结构，第一次拆解，可能只能将第一层的键展开成列
    • 但有些列的值仍然是列表，这时候就需要继续拆解，直到所有的列都不是列表为止

    我们可以先将整个拍卖记录都转成一个 tibble，并概览一下它的结构：

    auctions_tbl <- tibble(record = auctions_nested)

glimpse(auctions_tbl)

    Rows: 1,000
Columns: 1
$ record <list> ["AUC00000", "Samsung Galaxy S22", "Electronics", "2025-07-19T, ...]
    • 这里，我们得到了一个 1000 行 1 列的 tibble，每行代表一条拍卖记录
    • 但所有的信息都被塞在了 record 这一列的单元格里

    (a) 拆解顶层键¶

    首先，我们来展开顶层键，我们使用 unnest_wider() 将 record 列中的顶层键展开为各自的列：

    auctions_tbl <- 
  auctions_tbl |> 
  unnest_wider(record)

glimpse(auctions_tbl)

    Rows: 1,000
Columns: 9
$ item_id     <chr>  "AUC00000", "AUC00001", "AUC00002", ...
$ title       <chr>  "Samsung Galaxy S22", "Casio G-Shock Watch", "Louis Vuitton Handbag", ...
$ category    <chr>  "Electronics", "Fashion", "Fashion", ...
$ start_time  <chr>  "2025-07-19T08:04:31.226153", "2025-04-24T00:50:00.330964", ...
$ end_time    <chr>  "2025-07-20T08:04:31.226153", "2025-04-27T00:50:00.330964", ...
$ seller      <list> ["pray", 4.63, "AE"], ["vgomez", 3.6, "MY"], ...
$ bids        <list> [["istevens", 94.61, "2025-07-19T10:41:31.226153"], ["mendozajasmine", 97.73, "2025-07-19T13:27:31.226153"], ...]
$ final_price <dbl>  161.57, 135.53, 37.19, ...
$ winner_id   <chr>  "smithkayla", "mayercheyenne", "jessica58", ...

    到了这一步，我们发现：

    • 列表的顶层键：item_id、title、category、start_time、end_time、seller、bids、final_price、winner_id 都被展开成了独立的列
    • 之后，还需要继续拆解 seller 和 bids 这两列，因为它们的值仍然是列表
    • seller 这一列中的每个元素依然是一个列表
    • bids 这一列中的每个元素更复杂，每个元素都是列表套列表的结构

    并且，seller 和 bids 这两列在后续展开的时候，应对方式是不同的：

    • seller 属于是长度相同的嵌套键，它的每个列表元素都包括了相同的键，因此我们在展开时可以将这些键直接展开成独立的列
    • bids 属于是长度不相同的嵌套键，因为每条拍卖记录的出价数量不同，因此我们在展开时需要将每条出价展开成独立的行，而不是独立的列

    (b) 拆解相同长度嵌套键¶

    之后，我们先将 seller 列展开成独立的列，这一列中的每个列表都有相同的键：

    • unnest_wider() 会将 seller 列中的每个列表元素的键展开成独立的列
    • 指定 names_sep = "_" 参数的作用是将列名以 seller_ 开头：
    auctions_tbl <- 
  auctions_tbl |> 
  unnest_wider(seller, names_sep = "_")

    (c) 拆解不同长度嵌套键¶

    对于 bids 列，来说：

    • 如果和 seller 列一样用 unnest_wider() 将每条出价展开成独立的列，那么就会变得非常复杂：

      • 每条出价都需要展开成独立的列，例如 bids_1、bids_2 等

      • 比方说，第1条拍卖记录有 2 条出价，第2条拍卖记录有 3 条出价，那么就需要创建 bids_1、bids_2、bids_3 等列：

        • 这时第一条拍卖记录的 bids_3 列就会是 NA，因为它只有 2 条出价
        • 这时第二条拍卖记录的 bids_3 列就会有值，因为它有 3 条出价

      • 而整个数据集中，bids_ 会展开到多少呢，这取决于最多出价数量的那一条拍卖记录有多少条出价，这个我们是事先不知道的

    • 并且，由于每条出价又是一个列表，里面包含了 bidder_id、amount、time 等键：

      • 因此每条出价展开成独立的列以后，这些列本身又是列表，这就需要继续使用 unnest_wider() 函数展开
      • 而我们并不知道 bids_ 列会展开成多少列，所以我们不知道要调用多少次 unnest_wider() 函数
