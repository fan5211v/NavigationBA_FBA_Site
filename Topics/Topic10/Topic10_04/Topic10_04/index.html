    Topic 10.4 - 数据存储：数据库¶

    1. 数据库简介¶

    数据库大家可以简单理解为一个存储数据的容器：

    • 数据库存储的数据格式可以是表格，也可以是类似于 JSON 的层次化结构
    • 但是数据库和 CSV、Excel、JSON 等文件的最大区别是，数据库里的数据并不直接可见
    • 用文本编辑器或 Excel 等软件，是无法直接打开数据库文件的
    • 数据库中的数据长什么样，只有通过查询才能看到

    数据库被广泛使用的原因：

    • 高效存储：数据库在存储数据方面非常高效
    • 标准化查询语言：有一种广泛使用的语言 SQL（Structured Query Language，结构化查询语言） 专门用于对数据库进行数据整理
    • 支持多用户访问：数据库允许多个用户同时访问和修改数据，适合组织级共享

    • 多平台支持：数据库可以和各种编程语言和工具集成，支持复杂的数据分析和应用开发，例如：

      • 在 R 中我们可以通过一些手段读取成 tibble 来分析
      • 在 Python 中我们可以通过一些手段读取成 pandas 的 DataFrame 来分析

    数据库一个相关的概念叫做 Database Management System（DBMS），也就是数据库管理系统

    • 数据库管理系统是一个软件系统，负责创建、管理和查询数据库

    • 大家可以理解为：

      • 数据库是一个存储数据的容器
      • 数据库管理系统是负责对数据库进行操作的软件

    • 数据库管理系统主要有三种形式：

      • 客户端-服务器 DBMS：如 MySQL、PostgreSQL、SQL Server、Oracle

        • 运行在强大的中央服务器上，这个服务器通常是大公司买来的电脑，专门用来存储和管理数据库，由 IT 团队维护
        • 用户从自己的电脑，也就是客户端，连接到它
        • 适合在组织内多人共享数据

      • 云端 DBMS：如 Snowflake、Amazon Redshift、Google BigQuery

        • 类似于客户端-服务器 DBMS，但运行在云端，由云服务商提供和维护
        • 比方说公司想要一个 4核 CPU、16GB 内存、1TB 存储的数据库服务器，云服务商会提供这样的资源
        • 但是这个服务器具体部署在云服务商的哪个电脑上，用户无法知道，也不需知道
        • 云端 DBMS 可以轻松处理极大规模的数据集，并根据需要自动提供更多计算资源
        • 当资源不够的时候可以灵活扩展，适合处理大规模数据和多团队共享

      • 进程内 DBMS：如 SQLite、duckdb

        • 完全运行在用户的电脑上，能找到具体的数据库文件（但是文本编辑器打不开）
        • 适合个人使用或小团队共享数据，尤其适合数据科学家在本地分析数据

    2. 在 R 中连接数据库¶

    我们本节课为大家简单介绍以下 duckdb 这个进程内 DBMS：

    • 对于大家来说，duckdb 相对于其他抽象的数据库，一个有点就是它有一个实实在在的 .duckdb 文件，可以直接在文件系统中看到
    • 但是这个文件并不是一个文本文件，无法直接打开查看内容，必须通过数据库连接来访问其中的数据
    • 好消息是，duckdb 中的数据格式依然是表格形式，不会像 JSON 那样搞层层嵌套
    • 一个 duckdb 数据库文件会存储多张表，类似于 Excel 工作簿中的多个工作表

    在 R 中连接 duckdb 数据库需要两个包：

    • DBI：数据库接口，提供一组通用函数
    • duckdb：数据库引擎，存储和查询数据

    我们先来连接到拍卖数据库文件 auctions.duckdb：

    library(DBI)
library(duckdb)

con <- dbConnect(duckdb(), dbdir = "auctions.duckdb")

print(con)

    <duckdb_connection 87a30 driver=<duckdb_driver dbdir='/NavigationBA_FBA/codes/Topics/Topic09/auctions.duckdb' read_only=FALSE bigint=numeric>>

    这里，我们将数据库连接对象命名为 con：

    • 这个对象并不是表格，而只是一个数据库链接，它链接了 R 与 auctions.duckdb 这个数据库文件
    • 如果我们后续需要这个数据库中的数据，我们再现用现根据需求从 con 这个连接中查询数据就可以了

    之前我们介绍过，一个数据库可以存储多张表：

    • 我们可以查看 auctions.duckdb 数据库中存储了哪些表：
    dbListTables(con)

    [1] "auctions" "bids" "sellers"
    • 并且，我们可以查看具体某张表的内容：
    tbl(con, "bids") |> 
  glimpse()

    Rows: ??
Columns: 4

$ item_id    <chr>  "AUC00000", "AUC00000", "AUC00000", "AUC00000", "AUC00000", ...

$ bid_time   <dttm> 2025-07-19, 2025-07-19, 2025-07-19, 2025-07-19, 2025-07-19, ...

    这里的 tbl(con, "bids")：

    • 看似是将 auctions.duckdb 数据库中的 bids 表读取成了一个 tibble，但实际上是一个惰性的数据库查询对象
    • 如果将表中的行数打印出来，会发现它显示为 Rows: ??，而不是具体的行数
    • 因为我们这里并没有把数据全部查询出来，所以 R 是不知道这个表具体有多少行的，只有当我们真正查询数据时，才会知道行数是多少
    • 结果中的 Database: DuckDB 1.5.2 [...] 表示这个对象是一个数据库查询对象，而不是一个真正的 tibble

    如果要将数据库中的数据查询出来，我们需要使用 collect() 函数：

    tbl(con, "bids") |> 
  collect() |>
  glimpse()

    Rows: 13,414
Columns: 4
$ item_id    <chr>  "AUC00000", "AUC00000", "AUC00000", "AUC00000", "AUC00000", ...
$ bidder_id  <chr>  "istevens", "mendozajasmine", "james22", "wnunez", "paynejohn", ...
$ bid_amount <dbl>  94.61, 97.73, 103.28, 119.04, 123.86, 127.30, 122.36, 103.28, ...
$ bid_time   <dttm> 2025-07-19, 2025-07-19, 2025-07-19, 2025-07-19, 2025-07-19, ...

    这里我们可以看到：

    • collect() 函数可以将数据库中的数据查询出来，并将结果返回给 R，转换成一个真正的 tibble
    • 并且，我们可以看到这个表有 13,414 行了，表明我们已经成功地将数据库中的数据查询出来了
    • 还有一个值的注意的是，Database: DuckDB 1.5.2 [...]，这个输出没有了，因为现在我们已经将数据查询出来了，数据已经在 R 中了，不再是一个数据库查询对象了，所以不再显示数据库的信息了
    • 但是大家要注意，这个 collect() 函数会将整个表的数据查询出来，我们这里的数据库体量是比较小的，所以全部查询出来也无关紧要，
    • 如果这个表非常大，全部查询出来可能会导致内存不足，所以在实际使用中，我们通常会先对数据库中的数据进行一些筛选和聚合，减少数据量后再使用 collect() 将结果查询出来，这样可以更高效地使用数据库资源

    3. 在 R 中处理数据库数据¶

    连接数据库后，可以开始整理数据了：

    • 在 tidyverse 中与数据库进行数据整理使用 dbplyr 包
    • 这个包表面上来看和 dplyr 非常相似，写的函数也和 dplyr 一模一样
    • 但它的底层实现是将这些函数转换成数据库查询语句，然后在数据库中执行查询，最后将结果返回给 R
    • 并且一定要注意使用 collect() 函数将结果查询出来，否则你得到的只是一个数据库查询对象，而不是一个真正的 tibble

    比方说，我们筛选出拍卖 AUC00001 的所有出价：

    bids_filtered <-
  tbl(con, "bids") |>
  filter(item_id == "AUC00001") |>
  collect()

glimpse(bids_filtered)

  tbl(con, "auctions") |>
  left_join(tbl(con, "sellers"), by = "seller_user_id")

res <- auctions_sellers |> 
  left_join(tbl(con, "bids"), by = "item_id") |> 
  collect()

    • auctions_sellers 是一个数据库查询对象，表示将 auctions 表和 sellers 表进行连接后的结果，但它并没有真正查询出数据来，因为它没有使用 collect() 函数，所以它只是一个数据库查询对象
    • res 是一个真正的 tibble，表示将 auctions_sellers 与 bids 表进行连接后的结果，并且已经使用 collect() 将数据查询出来
    • 注意，在进行表连接的时候，只能是链接和链接之间进行，或者 tibble 和 tibble 之间进行，不能是链接和 tibble 进行
