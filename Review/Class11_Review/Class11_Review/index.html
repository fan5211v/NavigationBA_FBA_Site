    Class 11 知识点总结¶

    Class 11 讲的是数据获取，事实上本门课我们只涉及 API 这一种数据获取方式：

    • 数据的三种类型：结构化、半结构化、非结构化
    • API：API 的基本概念及用法

    1. 数据的三种类型¶

    本节我们讲的数据三种类型，其实和上一节数据存储的类型有类似和重复的地方：

    • 结构化数据：有行有列的表格

      • 也就是我们上节课讲到的 Excel、Google Sheets、CSV、TSV、DuckDB 数据库，以及读取到 R 中的 tibble 和读取到 Python 中的 DataFrame，都是以 表格的形式存储数据，都是结构化数据
      • 优点是易存储、查询和分析，适合用 SQL 或 dplyr 处理
      • 缺点是建立和维护成本高，使用范围有限，难以处理非结构化数据

    • 半结构化数据：有标签和层次，但不像表格那样整齐

      • 也就是我们上节课介绍的 JSON，以及 HTML 文档、电子邮件等，都属于半结构化数据
      • 优点是灵活，能保留层次关系，适合用 JSON 解析工具处理
      • 缺点是分析前需要大量预处理，像我们上节课那样把 JSON 展开为表格，否则不能直接用表格处理工具

    • 非结构化数据：没有固定模式

      • 也就是文字、图片、音频、视频等，都属于非结构化数据
      • 优点是内容丰富、普遍存在
      • 缺点是处理复杂，需要专门工具（如 NLP、计算机视觉、AI）

    从结构化到非结构化的特点是：越来越不整齐，但越来越灵活、内容越丰富

    2. API 的基本概念¶

    (1) API 的定义¶

    API（应用程序接口）：计算机程序之间的一套标准规则：

    • 简单理解就是：用代码（R、Python），通过互联网，向数据提供方要数据，而不是手动下载 CSV 等其他形式的数据

    • 我们之前给大家举的例子是，Twitter（X）的 API：

      • Twitter 公司有自己的数据库，存储着帖子的数据
      • 大家使用 Twitter 的手机软件，就是把 Twitter 数据库里的数据，调用到你的手机上
      • 如果使用 Twitter 的 API，就是把 Twitter 数据库里的数据，调用到你正在写代码的程序里

    • API 最常返回的数据格式是 JSON：它能表示层次和嵌套，同时是文本，体积小，易传输和解析

    (2) 使用 API 的工作流程¶

    1. 阅读 API 文档：它说明能获取什么数据、怎么用
    2. 获取 API 密钥：相当于账号密码（有的 API 不需要）
    3. 发起 API 请求：用代码告诉 API 我们要什么数据
    4. 解析 JSON 响应
    5. 转化为可分析的表格：也就是我们在 Class 10 学过的矩形化操作

    3. 使用 API 请求与获取数据¶

    (1) API 请求的组成¶

    一个 API 请求，其实就是一个网址：基础网址 + 端点 + ? + 参数

    https://api.music-to-scrape.org/charts/top-tracks?week=42&year=2023&limit=100
|____________基础网址___________||______端点_______||__________参数____________|

    • 基础网址 Base URL：

      • 标识这个 API
      • 在上面的例子中是 https://api.music-to-scrape.org

    • 端点 Endpoint：

      • 基础网址后面的路径，标识想要哪类数据
      • 在上面这个例子中是 /charts/top-tracks，表示想要获取排行榜的热门歌曲

    • 参数 Parameters：

      • 描述想要什么样的数据：
      • 写在 ? 之后，用 & 连接
      • 在上面的例子中是 week=42&year=2023&limit=100，表示获取第 42 周、2023 年、限制 100 条数据

    (2) 发起 API 请求¶

    课上讲的发送请求是用 httr2 包中的函数构建请求与发送请求：

    • 例如，我们想在上方的 API 中获取排行榜的热门歌曲，可以这样写：
    library(httr2)

resp <-
    request("https://api.music-to-scrape.org") |>      # 基础网址
    req_url_path_append("charts", "top-tracks") |>     # 端点
    req_url_query(limit = 5) |>                        # 参数
    req_perform()

resp   

    <httr2_response>
GET https://api.music-to-scrape.org/charts/top-tracks?limit=5
Status: 200 OK
Content-Type: application/json
Body: In memory (366 bytes)

    • 在这段代码中，我们使用三个函数构建请求：

      • 我们使用 request() 函数指定基础网址，req_url_path_append() 指定端点，req_url_query() 指定参数
      • 这三个函数放在一起，才完整描述了我们想要发送的请求
      • 但是这三个函数只是构建请求，没有真正发送请求

    • 之后我们用 req_perform() 真正发送请求，得到响应对象 resp

    (3) 响应的状态码¶

    在 resp 对象中，我们可以查看到 200 的状态码，表示请求成功

    • 除此之外，还有一些常见的状态码类别：
    状态码 含义
    2xx（如 200） 成功
    4xx（如 404 Not Found） 请求有问题（网址写错、没权限等）
    5xx 服务器出了问题
    • 注意，看到 200 才表示请求成功
    • 请求如果失败，R 并不会报错，所以需要主动检查状态码，没报错不代表成功
